# 多数据库支持指南（9 库对应关系）

> 工程目标数据库：**db2、dm（达梦）、highgo（瀚高）、kingbase（人大金仓）、mysql、opengauss、oracle、postgresql、sqlserver**。
> 核心思路：**不维护 9 套 SQL**——4 个信创库按方言兼容性归并到主流家族，全部落点收敛为 **6 个方言 + 5 套迁移 SQL + h2 本地基线**。

## 1. 方言归并与 Flyway 迁移目录

| 数据库 | 方言家族 | Flyway 迁移目录 | 本地 H2 对应 MODE |
|---|---|---|---|
| mysql | MySQL | `db/migration/mysql/` | `MODE=MySQL` |
| oracle | Oracle | `db/migration/oracle/` | `MODE=Oracle`（现状） |
| **dm（达梦）** | **Oracle** | 复用 `oracle/` | `MODE=Oracle` |
| postgresql | PostgreSQL | `db/migration/postgresql/` | `MODE=PostgreSQL` |
| **opengauss** | **PostgreSQL** | 复用 `postgresql/` | `MODE=PostgreSQL` |
| **highgo（瀚高）** | **PostgreSQL** | 复用 `postgresql/` | `MODE=PostgreSQL` |
| **kingbase（人大金仓）** | **PostgreSQL**（PG 兼容模式） | 复用 `postgresql/` | `MODE=PostgreSQL` |
| sqlserver | SQL Server | `db/migration/sqlserver/` | `MODE=MSSQLServer` |
| db2 | DB2 | `db/migration/db2/` | `MODE=DB2` |

约定（对应 AGENTS.md §2.6）：每个方言家族一份迁移，h2 一份本地基线，**成对维护**；
已合并的 `V*.sql` 永不修改，只追加（**上线前例外**：项目未上线时曾于 2026-09 把各目录多版本
V 文件合并为每目录单 V1——system V1+V2、job V1~V3、gen V1+V2、audit oracle V1+V3；上线后此例外
不再适用）。只有当某个库真出现方言差异时才拆独立目录。

### 基线生成与维护（scripts/gen_dialect_migrations.py）

家族基线**由脚本从 h2 基线翻译生成**，不要手工编辑生成文件（头部带 `GENERATED-BY` 标记）：

```bash
python scripts/gen_dialect_migrations.py --force   # h2 基线演进后重新生成
```

- **h2 是事实源**：改表结构先改 `db/migration/h2/V*.sql`（Flyway 只追加），再 `--force` 重新生成全部家族；
- 脚本只覆盖带 `GENERATED-BY` 标记的文件——`services/audit`、`services/message` 手工维护的
  `oracle/` 基线永远不会被覆盖（audit/message 的 oracle 为手工维护，audit 的已合并 V1+V3 为单文件）；
- 翻译规则：类型映射（VARCHAR2→NVARCHAR/LONGTEXT/BYTEA/VARBINARY(MAX) 等）、identity 方言化
  （AUTO_INCREMENT / IDENTITY(start,inc) / GENERATED BY DEFAULT AS IDENTITY）、注释方言化
  （COMMENT ON / MySQL 内联 COMMENT / SQL Server 扩展属性 sp_addextendedproperty）、
  schema 前缀剥离、`SYSTIMESTAMP` 等令牌映射、SQL Server 种子数据的 `SET IDENTITY_INSERT` 包裹；
- 生成后用 H2 对应兼容模式做语法冒烟（mysql/sqlserver 先规范化方言专有语法），真实库行为
  仍按 §6 清单回归。

## 2. JDBC 驱动与 Flyway 模块（版本一律走 BOM）

服务 pom **按目标库以 `runtime` scope 挑选引入**，不要全量堆进 classpath：

| 数据库 | 驱动坐标（BOM 已收口） | driver-class-name | URL 前缀 |
|---|---|---|---|
| mysql | `com.mysql:mysql-connector-j` | `com.mysql.cj.jdbc.Driver` | `jdbc:mysql://` |
| oracle | `com.oracle.database.jdbc:ojdbc11` | `oracle.jdbc.OracleDriver` | `jdbc:oracle:thin:@` |
| dm | `com.dameng:DmJdbcDriver18` | `dm.jdbc.driver.DmDriver` | `jdbc:dm://` |
| postgresql | `org.postgresql:postgresql` | `org.postgresql.Driver` | `jdbc:postgresql://` |
| kingbase | `cn.com.kingbase:kingbase8` | `com.kingbase8.Driver` | `jdbc:kingbase8://` |
| highgo | `com.highgo:HgdbJdbc` | `com.highgo.jdbc.Driver` | `jdbc:highgo://` |
| opengauss | `org.opengauss:opengauss-jdbc` | `org.opengauss.Driver` | `jdbc:opengauss://` |
| sqlserver | `com.microsoft.sqlserver:mssql-jdbc` | `com.microsoft.sqlserver.jdbc.SQLServerDriver` | `jdbc:sqlserver://` |
| db2 | `com.ibm.db2:jcc` | `com.ibm.db2.jcc.DB2Driver` | `jdbc:db2://` |

Flyway 13.x 起按 ServiceLoader 发现数据库，每个库一个独立模块，**部署时按目标库引入对应模块**：

| 目标库 | Flyway 模块 |
|---|---|
| mysql / mariadb | `org.flywaydb:flyway-mysql` |
| oracle / dm（见下文限制） | `org.flywaydb:flyway-database-oracle` |
| postgresql / opengauss / highgo / kingbase（见下文借道） | `org.flywaydb:flyway-database-postgresql` |
| sqlserver | `org.flywaydb:flyway-sqlserver` |
| db2 | `org.flywaydb:flyway-database-db2` |
| h2（本地默认） | flyway-core 内置 |

`flyway.locations` 从写死的 `classpath:db/migration/h2` 改为按部署目标库在 Nacos profile 里指定
（如生产 Oracle：`classpath:db/migration/oracle`）。

## 3. Flyway 对信创库的现实约束

- **openGauss / HighGo / Kingbase（PG 兼容模式）**：无官方 Flyway 模块，但服务端兼容 PG 协议，
  实践中用 **PostgreSQL 驱动**（`jdbc:postgresql://`）+ `flyway-database-postgresql` 可直接运行
  （Kingbase V8R6 基于 PG 12 内核、openGauss 基于 PG 9.2 内核）。**每个库接入前须用真实库回归一次**
  迁移执行与 `flyway_schema_history` 写入。
- **达梦 DM**：协议不冒充 Oracle、Flyway 无任何模块（社区版/Teams 版都没有），Flyway 会在
  连接期报 Unsupported Database。走法二选一：
  1. `oracle/` 目录的 SQL 由达梦 DTS 等工具人工导入（RuoYi 系传统做法）；
  2. 不用 Flyway，改用 Spring `DataSourceScriptDatabaseInitializer` 或自维护
     `flyway_schema_history` 语义的轻量脚本执行器。
- **Kingbase Oracle 兼容模式**：语法上可复用 `oracle/` 目录，但其 Flyway/驱动行为未经验证，
  接入前先实测；默认按 PG 家族处理。

## 4. 分页与多数据源（零代码改动）

- **分页**：Spring Data `Pageable`（`PageUtils.toPageRequest(PageDomain)` 构建），方言 LIMIT 由
  Hibernate 按各库方言渲染（top-N 不再写 `FETCH FIRST`/`ROWNUM`/`LIMIT`，也无需 PageHelper）。
- **dynamic-datasource（baomidou）**：`DbType` 枚举覆盖全部 9 库
  （含 `DM / KINGBASE_ES / HIGH_GO / GAUSS / OPENGAUSS`），按 URL 自动识别，零配置。

## 5. ORM 层的方言纪律（JPA）

1. **业务查询由 Hibernate 方言接管**：JPQL/`JpaSpecs` 动态条件跨库安全，无需手写方言分支；
   top-N 用 `Pageable`；日期区间用 `JpaSpecs.dateRangeIf`（内部解析 params.beginTime/endTime，
   整天包含语义与原 mapper 纯比较一致）。
2. **原生 SQL 门禁**：`@Query(nativeQuery=true)` 出现方言专有构造
   （`SYSDATE`/`TO_CHAR`/`||`/反引号…）会被 `ArchTestSupport` 直接红——原生查询必须写可移植 SQL
   （如 audit 的跨域只读快照），子类可用 `nativeQueryExcludedClasses()` 显式登记豁免。
3. **确需方言差异时（查数据库目录/元数据）：服务层分发**，参照 `GenCatalogDao`——
   5 个真实方言各自目录 SQL 原样维护 + H2/未识别库走 JDBC `DatabaseMetaData` 兜底，
   方言由 `DatabaseDialects.resolve(dataSource)` 解析（工具在
   `com.scaffold.common.core.jpa.DatabaseDialects`，产品名包含式匹配归并信创库），
   方言分支由单测锁定（`GenCatalogDaoTest`）。
4. **驱动与 `flyway-database-*` 模块版本走 BOM**，服务按目标库以 runtime scope 引入；
   DDL 仍按 §3 家族基线成对维护，Flyway 纪律（只追加）不变。

### gen 逆向查询的方言覆盖范围（GenCatalogDao，5 方言 SQL + JDBC 元数据兜底）

| 方言 | 表目录 | 列目录 | 已知限制 |
|---|---|---|---|
| mysql | `information_schema.tables` | `information_schema.columns` | — |
| oracle | `user_tables` + `user_tab_comments` | `user_tab_columns` + `user_col_comments` | 达梦的 `identity_column` 字典列需在目标版本实测 |
| postgresql | `pg_class` + `obj_description` | `pg_attribute` + `col_description` | PG 系目录无可靠建表时间，列表时间过滤不生效 |
| sqlserver | `sys.tables` + `sys.extended_properties` | `sys.columns` | — |
| db2 | `syscat.tables` | `syscat.columns` + `syscat.keycoluse` | — |

`column_type` 统一归一成 MySQL 风格字符串（如 `varchar(64)`、`number(10)`、`decimal(10,2)`），
因为 `GenUtils.getDbType/getColumnLength` 按该格式解析推导 Java 类型。
信创库产品名可能因版本/兼容模式不同（金仓 PG 模式下驱动直接报 PostgreSQL），新库接入时先跑
`connection.getMetaData().getDatabaseProductName()` 验证，必要时在
`DatabaseDialects` 补登记条目（有单测兜底）。

## 6. 新库接入检查清单

1. BOM 加驱动版本条目（说明用途），服务 pom 以 runtime scope 引入；
2. 引入对应 `flyway-database-*` 模块（信创库按 §3 的借道/绕行策略）；
3. Nacos 部署 profile 配 `flyway.locations`（分页方言由 Hibernate 自动识别，无需额外配置）；
4. 家族基线由脚本生成：改 h2 → `python scripts/gen_dialect_migrations.py --force`（见 §1）；
5. **真库回归**：`python scripts/regress_family.py --family <家族> --host <host> --user <user> [--password ...] [--service system]`
   ——建一次性库→执行基线→内容级验证（表数/列注释/种子/V3 补列/gen 逆向查询，见脚本
   `CHECKS`）→自动清理；postgresql/mysql 开箱即用，oracle/sqlserver/db2 等用 `--exec-cmd`
   模板接各库客户端；`--keep` 保留库人工核查。gen 逆向查询的验证挂在 system 库（业务表所在）。
6. 用真实库回归：Flyway 全量迁移、gen 服务逆向导入全流程、核心业务 mapper 冒烟；
7. 产品名与 `DatabaseDialects` 映射核对，必要时补条目 + 单测。
